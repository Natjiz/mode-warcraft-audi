# Генерация по запросу — 0.6.0

Код и пакеты подготовлены. Публичный Space пока **не размещён**: в этой среде
нет подключённой учётной записи Hugging Face. `companion/service.json` поэтому
содержит `space_url: null`. Готовые записи продолжают работать как в 0.5.0.

## Работа для игрока

Запуск остаётся прежним: EXE, игра и диалог квеста. Новый клиент сначала проверяет
готовый каталог и кэш, затем общую библиотеку Space. При промахе запускается
синтез; следующему игроку и после перезапуска сервиса возвращается сохранённый
результат. Адрес сервиса клиент получает из небольшого JSON проекта. Вводить
адрес/ключи или открывать браузер игроку не нужно. Запускающийся Space ожидается
автоматически до двух минут; смена/закрытие квеста отменяет поздний старт звука.

У клиента остаётся кэш 300 МБ. Записи скачиваются по SHA-256 и проверяются по
размеру. Последняя корректная конфигурация сервиса сохраняется для повторного
воспроизведения без сети. Ревизия правил голосов позволяет отсеять старые записи
кэша после исправления голоса. Утверждённые голоса Акунды/Киро не заменены.

## Сервис и постоянная библиотека

Gradio JSON API: `lookup` работает без GPU; `generate` под блокировкой повторно
проверяет запись и только потом вызывает `spaces.GPU`. Очередь — 16 задач,
одновременно создаётся одна новая запись. Время GPU запрашивается по длине текста
и наличию эталона, максимум 120 секунд. Два одинаковых запроса к одному Space
не синтезируются повторно. Аудио имеет неизменяемый путь по SHA, метаданные и
голосовые эталоны публикуются одним атомарным commit в публичный HF dataset.
Пути разделены по двум символам хеша, чтобы библиотека не росла одной большой
папкой. Dataset переживает остановку и перестроение Space.

Известные записи по-прежнему находятся на GitHub. Для новых записей используется
HF dataset того же владельца: это не требует передавать GitHub-учётные данные
серверу. Секрет записи dataset остаётся в настройках Space; в ZIP его нет.
Перед публикацией удаляются переданное имя игрока и посторонние поля запроса;
снимки экрана не отправляются. Ревизия зависит от конкретного NPC/эталона:
изменение карточки другого NPC не обнуляет всю серверную библиотеку.

## Голос под персонажа

Сначала используется отдельная карточка NPC и принятый эталон. Для остальных
добавлены направления по виду/расе и полу: вульпера, гном, гоблин, таурен,
тролль, дворф, орк, эльф, человек, дракон. Вид `Humanoid` сам по себе не
объявляется человеком. Недостаточные данные о внешности остаются явно
неподтверждёнными; генератор не определяет внешний вид по одному NPC ID.

Для небольших существ задаётся лёгкая подача; бас Акунды не является общим
вариантом. Новый эталон сохраняется между квестами и перезапусками. Пробы новых
NPC остаются кандидатами. Проверяются целостность весов/эталона, длина,
сигнал и основной тон: при слишком низком/высоком регистре делаются ограниченные
повторные попытки, неудачная запись не публикуется. Тон сравнивается и с эталоном,
и с диапазоном профиля. Акустическая проверка не заменяет художественное
прослушивание и не гарантирует правильность каждого ударения.

## Бесплатные ограничения

Клиент 0.6.0 обращается без пользовательского HF-ключа: по текущим условиям
ZeroGPU это **2 минуты GPU в сутки без входа**, с очередью. У бесплатного
авторизованного посетителя платформа даёт 5 минут, но вход в HF в обычный клиент
сейчас не добавлен. Ключи из среды игрока автоматически не пересылаются:
подключение платных кредитов не входит в эту реализацию. Готовые записи,
проверка библиотеки и локальный кэш не выделяют GPU.

Реальная скорость/квоты ZeroGPU ещё не измерены. Публикация Space требует
подходящего аккаунта с подтверждённой почтой старше 30 дней; при отказе
бесплатного ресурса скрипт не выбирает платную машину.

## Проверка здесь

Проверена настоящая генерация ранее отсутствовавшего в каталоге текста квеста
48314 «Медленная смерть», этап progress, Киро: PyTorch 2.8 CPU, Gradio 6.16,
настоящий HTTP/SSE клиент, скачивание, SHA, FFmpeg и повтор без нового синтеза.
Отдельно проверяется синтетический NPC-вульпера без готовой карточки: создаётся
новый неутверждённый эталон, результат сохраняется и переиспользуется.
Это не тест облачного ZeroGPU, настоящего WoW или физического звука.

Команды разработчика:

```sh
python -m unittest discover -s tests -v
python tests/space_smoke.py --engine fixture
python tests/space_smoke.py --engine qwen --output dist/space-qwen-smoke
python tests/space_smoke.py --engine qwen --synthetic-profile vulpera --output dist/space-new-npc-smoke
```

Синтетический NPC 900000002 и тестовый квест 900000001 не публикуются в игровом
каталоге. Проверки Gradio без моделей также запускаются в `.github/workflows/space.yml`.

## Размещение — задача сопровождающего, не игрока

1. Подключить подходящий HF-аккаунт и настроить `HF_TOKEN` как защищённый секрет
   среды с правами на Space и отдельный dataset. Не добавлять его в Git/чат.
2. Проверить и собрать пакет: `python tools/package_space.py`.
3. Выполнить `python tools/deploy_space.py --owner PROFILE`. Скрипт использует
   SDK-авторизацию, создаёт публичные Space/dataset, задаёт переменную библиотеки
   и секрет и запрашивает исключительно ZeroGPU.
4. Дождаться запуска, проверить реальный `lookup/generate`, скачивание и повтор
   без GPU. Только после этой проверки перенести `dist/service-proposal.json`
   в `companion/service.json` и опубликовать конфигурацию на GitHub.

До шага 4 генерация у игроков намеренно не объявляется работающей. Нет нужды
повторно устанавливать аддон 0.5.0: изменена только Windows-программа и сервер.

Смена эталона/правил при размещении автоматически меняет отпечаток в предложении
конфигурации клиента. Неизменившаяся запись при этом находится по прежнему ID,
проверяется локально и не скачивается/не генерируется повторно. Кэш общего
сервера использует отдельные ревизии NPC.

Загрузка в настоящий HF dataset и настоящее выделение ZeroGPU ещё не проверены:
для этого нет настроенной HF-авторизации. Локальные тесты проверяют постоянную
библиотеку на диске, а не подменяют результатом тест облачного хранилища.
