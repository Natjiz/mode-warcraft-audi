# Генерация русской озвучки

Текущий статус: модель скачана, синтез выполнен. Созданы четыре записи для
«Благословения Акунды» (50913), включая оба обращения в описании. Файлы
сохранены в `assets/akunda`; архив — `dist/WarcraftAudi-0.2.0-Akunda.zip`.
Все записи декодированы FFmpeg, привязка этапов и путей проверена загрузкой
настоящего архива в Lua 5.1 с имитацией WoW API. Художественная подача и
поведение в WoW Circle требуют прослушивания и проверки в клиенте.
Сетевые настройки больше не блокируют работу.

Для сборки сохранённых записей без повторной генерации:

```sh
python tools/build_akunda.py
```

В этом комплекте `/wca demo` проигрывает реальное описание квеста с мужским
обращением; при общении с NPC пол персонажа учитывается.
[Подробности квеста](QUEST_50913.md).

Генератор работает вне WoW, на CPU, без платного API. Стартовые профили
задают тембр, темп и высоту: `commander` (eugene), `sage` (aidar), `scout` (baya),
`loa` (eugene, медленная пониженная подача — использован для Акунды).
Это пробы подачи, а не утверждённая актёрская озвучка Warcraft. Для финальной
записи нужно прослушивание, правки ударений и подбор подходящего голоса для NPC.

## Подготовка

В текущей облачной среде CPU PyTorch 2.6.0, NumPy 2.2.6 и SciPy 1.15.3 установлены в
`/workspace/.warcraft-audi-venv`, FFmpeg доступен. На другой машине:

```sh
python3 -m venv /path/to/voice-venv
/path/to/voice-venv/bin/python -m pip install \
  --index-url https://download.pytorch.org/whl/cpu 'torch==2.6.0+cpu'
/path/to/voice-venv/bin/python -m pip install 'numpy==2.2.6' 'scipy==1.15.3'
```

Также нужен FFmpeg с кодировщиком `libvorbis`. Дальнейшие команды выполняются
из корня репозитория; `python` означает интерпретатор выбранного окружения.

```sh
python tools/generate_voices.py fetch-model
```

Файл модели по умолчанию находится в `/workspace/.warcraft-audi-models/v5_ru.pt`,
вне Git-репозитория. Можно указать `--model /другой/путь/v5_ru.pt` **перед**
подкомандой. Загрузка использует обычную проверку HTTPS и записывает SHA-256
в соседний JSON. Этот хеш фиксирует скачанный файл, а не является подписью
издателя. Перед каждым запуском модель сверяется с этой записью. Ошибка
загрузки не оставляет частично готовой модели. Не загружайте чужие файлы
PyTorch PackageImporter: они могут содержать исполняемый код.

## Отдельная оригинальная проба голоса

После успешной загрузки модели:

```sh
python tools/generate_voices.py demo --profile commander \
  --output dist/original-audition.ogg
```

Подкоманда `demo` генерирует оригинальную реплику о Драконьих островах,
не являющуюся текстом квеста. Сборка Акунды вместо неё использует сохранённое
реальное описание. Не заменяйте его случайно. Сборка основного аддона с
`--with-demo` требует существования `addon/WarcraftAudi/Audio/demo.ogg`.

## Озвучка настоящих квестов

1. Сохраните JSON из `/wca export` как `quests.json` либо подготовьте его
   по той же схеме из проверенных текстов именно WoW Circle 10.2.7.
2. По желанию задайте каждому этапу `tts_profile`: `commander`, `sage`, `scout`, `loa`.
   Для одного NPC выбирайте один профиль. Поле `tts_text` позволяет исправить
   произношение без изменения исходного `text`; знак `+` перед ударной гласной
   поддерживается Silero. По умолчанию используется исходный текст и общий профиль.
   Необязательное поле `gender` (`male`/`female`) разделяет варианты обращения.
   Пример всех этапов: `quests/akunda_ruRU.json`.
3. Выполните генерацию и сборку:

```sh
python tools/generate_voices.py quests quests.json --profile commander \
  --audio-root dist/recordings --manifest dist/voiced-quests.json
python tools/package_addon.py pack dist/voiced-quests.json \
  --audio-root dist/recordings --name Dragonflight_ruRU \
  --output dist/WarcraftAudi_Dragonflight_ruRU.zip
```

Поддерживается язык `ruRU`. Длинные тексты разбиваются на фрагменты для синтеза,
затем объединяются в файл этапа. Результат — моно OGG Vorbis 48 кГц с нормализацией
громкости; FFmpeg декодирует каждый файл целиком для проверки контейнера/кодека.
Это не подтверждает правильность произношения: готовые реплики нужно прослушать.

Каждая запись получает JSON с параметрами и контрольной суммой. Повторный запуск
переиспользует совпадающие файлы; отличающиеся существующие записи не перезаписываются.
После прерывания запуска можно использовать тот же каталог записей и новое имя
манифеста. Манифест создаётся после завершения всех реплик. Входные записи с уже
заполненным `audio` отклоняются, чтобы не заменить готовую озвучку случайно.

Генератор не создаёт отсутствующие тексты и не обеспечивает сам по себе покрытие
всех квестов. Для этого нужен проверенный каталог квестов и их вариантов.
